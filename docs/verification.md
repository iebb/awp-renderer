# Verification

The initial standalone release was checked on 2026-10-25 in Japan time. `verification.json` is the fresh extracted-package parity report, not a report copied from the editor project.

The native suite uses six project-owned synthetic JSON examples (membership, boarding, event, coupon, rewards, and poster), front/Watch faces, and baseline/200,000-character values. Each package render is compared to a separately launched snapshot capture from the unmodified Pass Designer extension. The comparator checks image size, every raw RGBA channel including transparent RGB, and PNG color metadata. Test output PNGs and pass data remain in ignored local artifacts; only the synthetic result report is committed.

```sh
npm ci
npm run check
python3 -m pip install Pillow
npm run test:png
npm run test:native
```

The portable tests cover JSON/resources, deterministic ZIPs, invalid names/images, bounds, cancellation, exact-source enforcement, explicit approximate opt-in, HTTP authentication/origins/errors, and CLI validation. The clean-consumer check packs the actual release, installs it in a temporary project, imports the core without React, exercises React 18 SSR, and imports the server.

Browser verification also exercises JSON editing, malformed JSON without stale images, text stress input, width-only resizing, phone/Watch switching, and downloads through the standalone HTTP server. Marketing images use actual synthetic native output and reproducible SVG compositions, generated by `node scripts/marketing.mjs` after the native suite. `playground.png` is a real browser screenshot.

This proves the tested matrix on the recorded app/OS build. It is not evidence of all Apple versions, every possible JSON combination, real-device rendering, or public hosted production availability. A different native build needs its own report.

The default native suite runs sequentially to avoid competing extension hosts. During extraction, a concurrent stress run with other native work active produced one bounded Watch timeout (23/24 renders completed); that run is not reported as 24/24 success. Do not interpret exact successful pixels as a guarantee of zero timeouts under contention. Rendering failures remain errors and are not automatically retried.
